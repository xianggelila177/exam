# 试卷截图 → 打印稿

老师和家长常见的场景：在手机或 iPad 上看到一份试卷/讲义，一页页截图存下来，
结果每张图上下都是播放器黑边和“3/10”这样的页码条，直接打印会浪费墨、纸面歪、
字还发虚。这个 skill 把这堆截图变成能直接塞进打印机的稿件。

**不要假设一定存在“原卷/解析”两套。** 先通过 survey 看证据：

- 只检测到一套 → 输出一套；
- 明确检测到原卷和带答案解析版 → 分成两套；
- 无法可靠判断 → 保留原始分组并告诉用户，不要硬猜。

## 脚本位置

本 Skill 的所有确定性处理都放在 `scripts/prep_print.py`，SKILL.md 不内嵌代码。
调用时以本 Skill 目录为基准：

```bash
python3 scripts/prep_print.py --help
```

如果运行时报缺少 Pillow 或 NumPy，说明当前宿主环境没有安装依赖。
请先由宿主环境安装（例如 `python3-pil python3-numpy`），不要在脚本里临时 `pip install`。

## 工作流

四步走，不要跳过前三步。

### 第 1 步：survey — 先看清楚手里是什么

```bash
python3 scripts/prep_print.py survey <图片/目录/zip...> --sheet /tmp/sheet.png --dedupe
```

它产出：

- `/tmp/sheet.png` — 缩略图联表，看版式、找重复页、判断有没有答案解析。
- `/tmp/sheet_footers_001.png`、`/tmp/sheet_footers_002.png` … — 页脚拼贴，
  按每 12 页一批，避免页数很多时拼成一张超长图。先看这批图，页码往往一眼
  就把分组问题解决了。
- 裁剪诊断 JSON — 看 `cropped_ratio` 和 `kept_fraction` 判断裁剪是否合理。

这是整个流程唯一需要“用眼睛”的地方。看的时候回答三个问题：

1. **分几套？** 看页脚拼贴里的“第 X 页/共 N 页”。共 8 页的和共 10 页的显然
   是两套；同一套内页码应当 1→N 连续。缺页、重复页也在这里暴露。
   注意别被截图右上角“3/10”这种阅读器计数器骗了——它是当次滑动的进度，
   页脚才是文档自己的页码。
2. **哪套带答案？** 带答案的版本会出现【答案】【详解】【解析】【小问详析】
   这类标记，或者选项后面直接跟着正确选项。带解析的那套通常页数更多。
3. **裁剪对不对？** 诊断 JSON 里 `cropped_ratio` 接近 1.414 说明裁出来正好是
   A4 纸面；`kept_fraction` 特别小（比如 <0.3）说明裁过头了。这时候用
   `--thresh 100` 甚至 `--no-crop` 重来。

页脚在纸面上的位置各家排版不同，默认取底部 12%。如果拼贴里没看到页码，
用 `--footer-frac 0.2` 多取一点再看。

### 第 2 步：build — 每套单独跑一次

```bash
python3 scripts/prep_print.py build <这一套的图...> --out "无答案-试卷" --dedupe
python3 scripts/prep_print.py build <那一套的图...> --out "有答案-解析" --dedupe
```

传图片时按页序传；脚本会先按父目录分组，再按文件名自然排序，避免原卷/解析
同名文件交错。输出目录名就是 PDF 名，直接用中文的、用户一眼能懂的名字。

默认参数面向“手机截图的电子版试卷”：统一放进 A4@300dpi 白底画布（约
2480×3508），USM 锐化 130%、对比 1.18。`--target-width` 现在对大于或小于
目标宽度的图片都会生效，不是只放大不缩小。跑完看返回 JSON 里的
`dark_edge_warnings`——非空说明某页四边还有暗像素，黑边没裁干净，得回头调
`--thresh`。

### 第 3 步：verify — 处理完要看一眼成品

```bash
python3 scripts/prep_print.py verify "无答案-试卷" "有答案-解析" --sheet /tmp/verify_sheet.png
```

verify 会生成最终成品缩略图，并给出每套的页数、尺寸统计、边缘异常列表。
用当前环境可用的看图能力检查一遍：文字是否过锐、白边毛刺、内容被裁、
页面比例失真、页序错误、答案版分组错误。发现问题就回到 build 调参重做。

### 第 4 步：pack — 打成一个压缩包

```bash
python3 scripts/prep_print.py pack "无答案-试卷" "有答案-解析" --zip "化学试卷_打印版.zip"
```

zip 里保留两个文件夹的结构，每个文件夹里是 `01.jpg…NN.jpg` 加一份合并 PDF。
PDF 给“直接点打印”的人，JPG 给要挑页、要重排的人。用户如果明说“给我一个 PDF
就行”，就别打包，直接交 PDF。

## 参数怎么调

用户抱怨什么，就调什么。别一上来堆参数，默认值对干净的电子版截图已经够好了。

| 用户说 | 调什么 |
|---|---|
| 字还是虚 / 打印出来发灰 | `--sharpen 180 --contrast 1.3` |
| 锐化过头了，笔画有白边毛刺 | `--sharpen 80 --radius 2` |
| 底色发灰、有阴影（多见于拍照） | `--whitepoint 235`，更脏就 `225` |
| 想省墨 / 黑白打印机 | `--grayscale --ink-save`（可用 `--ink-limit 0.4` 调更低） |
| 打印出来纸边缘有黑线 | `--margin 8`，再不行 `--thresh 180` |
| 图被裁掉了内容 | `--thresh 100`；还不行 `--no-crop` |
| 文件太大发不出去 | `--target-width 1654 --quality 85 --no-fit-a4` |
| 就要图片不要 PDF | `--no-pdf` |

`--whitepoint` 是拍照场景的关键：它把亮度不低于该值的像素推成纯白，低于阈值
的浅色内容不会整体被提亮。定多少不要拍脑袋——先测一下纸面实际有多灰
（`np.percentile(灰度图, 95)`），测出来 225 就设 225。如果卷面上有铅笔写的
浅色答案，仍可能被抹掉，所以只在用户确实抱怨灰底、且卷面没有手写内容时用。

## 常见边界情况

- **省墨**：`--grayscale --ink-save` 会把大面积深色区域调淡到约 45% 墨量，同时尽量保留细笔画/文字的黑色。
- **重复页**：同一页截了两次很常见。survey/build 加 `--dedupe` 会按 MD5 去掉
  完全相同的文件。
- **横屏截图 / 双页拼在一张图上**：先用 `--no-crop` 出图，再用
  `python3 scripts/prep_print.py split <图...> --out split/` 按中缝切成左右两页，
  然后当两页处理。
- **图很多（>50 张）**：survey 用 `--cols 8` 让联表更紧凑，页脚已自动分批。
- **拍的照片而不是截图**：纸面可能是倾斜的、四角带桌面背景。亮度扫描只能裁出
  外接矩形，裁不掉倾斜。先如实告诉用户“这几张是斜的，裁边只能裁到矩形”，
  再问要不要接受。

## 交付

使用当前宿主提供的文件交付能力，把最终 PDF 或 ZIP 返回给用户。然后用两三句话
说明：分了哪几套、各多少页、做了什么处理。不要长篇复述流程。

如果 survey 或 verify 发现了不确定的地方，在交付时点出来让用户核对，别默默替
他们决定。最常见的三种：解析版页脚写“共15页”但只截到第10页；同一页截了两次；
文件名说的科目和卷面实际科目对不上。
